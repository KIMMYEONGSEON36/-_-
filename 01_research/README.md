# 사용자 리서치

## 문제 가설
- 디자인 요청이 메신저, 구두 등 여러 경로에 흩어져 정보와 자료를 다시 모아야 합니다.
- 요청자가 제작 목적, 규격, 필수 문구 등 필요한 정보를 빠뜨릴 수 있습니다.
- 디자이너가 요청을 다시 확인하고 작업 단위·시간·우선순위를 정리하는 데 시간이 듭니다.
- 진행 업무와 대기 업무, 마감일을 한눈에 파악하기 어렵습니다.

## 사용자 그룹
| 그룹 | 목표 | 주요 행동 |
| --- | --- | --- |
| 요청자 | 디자인 요청을 쉽고 정확하게 전달 | 유형 선택, 내용 입력, 자료 첨부, 제출, 상태 확인 |
| 디자이너 | 요청을 검토하고 업무를 관리 | 분석 검토, 작업 분해, 일정 조정, 진행·시간 기록 |

## 리서치 산출물
사용자 그룹, 페르소나, 인터뷰 인사이트, 여정 지도를 정리합니다. 현재 내용은 기획서에서 도출한 가설이며, 인터뷰로 검증된 사실과 구분해 기록합니다.

## 인터뷰 기록 템플릿
- 날짜 / 참여자 역할:
- 최근 디자인 요청 사례:
- 요청 과정에서 막힌 지점:
- 누락 정보 확인에 드는 시간과 방식:
- 업무 우선순위·일정 관리 방식:
- 인용 또는 관찰:
- 인사이트 / 후속 질문:
