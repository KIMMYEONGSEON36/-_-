# 제품 전략

## 문제 정의
디자인 요청의 정보가 흩어지고 불완전해, 디자이너가 내용을 재확인하고 작업·일정으로 변환하는 데 부담이 생깁니다.

## 전략 방향
요청자에게는 짧고 단계적인 접수 경험을 제공하고, 디자이너에게는 요청과 연결된 검토 가능한 작업 관리 공간을 제공합니다. AI는 요약·누락 정보·작업 분해·시간 및 일정 제안의 보조 역할에 한정합니다.

## MVP 성공 기준
- 비전문가가 디자인 요청을 제출할 수 있습니다.
- 요청 정보와 첨부 자료를 하나의 상세 기록에서 확인할 수 있습니다.
- 분석 제안을 디자이너가 수정·승인할 수 있습니다.
- 요청 하나를 여러 작업으로 나누어 상태를 관리할 수 있습니다.
- 예상 시간과 실제 시간을 기록하고 대시보드에서 마감·지연 업무를 파악할 수 있습니다.

## 우선순위 원칙
핵심 요청→검토→작업 생성→진행 관리 흐름을 먼저 검증합니다. 실제 AI API, 사내 연동, 팀 단위 기능은 기본 UI·데이터 구조·오류 처리가 검증된 뒤 별도 결정합니다.

## 미결정 사항
서비스명, 인증·상태 조회 권한, 저장소·배포 환경, AI 제공자와 데이터 정책, 첨부 제한·보관 정책, 시간 추정 보정 방식, 사내 플랫폼 연동 여부.
